# Telegram Task Parser Bot

Telegram-бот на aiogram для извлечения и отслеживания задач из сообщений. В одном процессе
он запускает polling Telegram и aiohttp-приложение для Mini App.

## Agent Office — архив / TODO

Интеграция Codex и Agent Office временно не используется. Вкладка Codex убрана из
Telegram Mini App, `/office/` не собирается и отвечает `410 Gone`; API канала и

Исходники прототипа и серверного канала сохранены для доработки. Состояние,
нерешённые вопросы и условия повторного включения описаны в
[`docs/agent-office-status.md`](docs/agent-office-status.md).

## Запуск

Требуется Python 3.11+ и PostgreSQL либо SQLite для локальной разработки.

```bash
python -m pip install -e .
python -m bot.app
```

Основные настройки читаются из `.env`: `BOT_TOKEN`, `DATABASE_URL`, `WEB_HOST`, `WEB_PORT`
и `WEB_BASE_URL`. Docker-вариант запускается командой `docker compose up -d --build`.

## DoQA PDF-парсер

PDF можно обработать одним из способов:

- приложить PDF к сообщению с подписью `/parse` или `#doqa`;
- ответить командой `/parse` на сообщение с PDF.

Бот подтверждает приём файла, обрабатывает его вне event loop, затем отправляет DOCX и ZIP.
Временная директория конкретного запуска удаляется после отправки обоих файлов.

Полный отчёт существующего DoQA-прогона можно сформировать ответом на нужное сообщение:

```text
/zip 385
```

Если в сообщении разработчика уже есть ссылка на прогон DoQA или текст `прогон #385`,
достаточно ответить на него одной командой `/zip`. Старая команда `/doqa_report 385`
также продолжает работать.

Число в команде — ID из названия прогона, например `ID 671`. Бот найдёт самый свежий
подходящий прогон через read-only DoQA API, сформирует временный PDF,
передаст его существующему PDF-парсеру и отправит ZIP ответом на выбранное сообщение. Временный
PDF пользователю не отправляется и удаляется вместе с рабочей директорией после отправки архива.
Ссылка на прогон, число тестов и багов будут в подписи ZIP.
Промежуточные сообщения о загрузке бот не отправляет: при успехе приходит только ZIP, а при
ошибке — короткое описание или код для поиска подробностей в журнале.
На сообщении с командой бот ставит `🫡`, когда принимает её в работу, и заменяет реакцию на
`👌` после успешной отправки архива.

Задание сохраняется в БД до начала обработки. Временные сетевые ошибки повторяются с
настраиваемыми задержками, а незавершённые задания восстанавливаются после перезапуска бота.
Если автоматические попытки закончились или ошибка требует исправления данных, бот пишет её в
чат. Ответ `повтори` на это сообщение сбрасывает число попыток и запускает тот же отчёт заново.
Повторная доставка одной команды Telegram не создаёт дубликат задания.
Отправленный ботом ZIP регистрируется в истории исходной задачи. Поэтому ответ разработчика
на сообщение с архивом связывается с той же задачей и может обновить или завершить её.

Если настроена QADB, автоматический `/zip` сначала фиксирует точную копию сформированного архива
в постоянном outbox, после чего отправляет её в Telegram. Синхронизация QADB выполняется отдельным
фоновым worker и не блокирует отправку пользователю. При недоступности QADB worker повторяет
загрузку тех же байтов с увеличивающимися задержками и продолжает после перезапуска контейнера.
Новый `/zip` для того же прогона создаёт новый снимок и после восстановления QADB заменяет там
предыдущую версию существующими upsert-операциями. Ручной ZIP из Mini App и `/parse` в outbox не
попадают.

Настройки парсера:

- `DOQA_PARSER_OUTPUT_DIR` — временная директория, по умолчанию `task_tracker_data/doqa_runs`;
- `DOQA_PARSER_MAX_INPUT_MB` — максимальный размер входного файла, по умолчанию 40 МБ;
- `DOQA_PARSER_MAX_PAGES` — максимальное число страниц, по умолчанию 250;
- `DOQA_PARSER_CONCURRENCY` — число одновременно обрабатываемых PDF, по умолчанию 1;
- `DOQA_PARSER_ALLOWED_USERNAMES` — usernames через запятую. Если не задано, используется
  `MINIAPP_ALLOWED_USERNAMES`; если оба значения пустые, парсер доступен всем пользователям бота.
- `DOQA_BASE_URL` — адрес DoQA без пути API;
- `DOQA_API_TOKEN` — bearer-токен только для чтения отчёта;
- `DOQA_REPORT_URL_TEMPLATE` — ссылка на прогон с плейсхолдером `{run_id}`;
- `DOQA_SPACE_ID` — ID пространства; необязателен, если определяется из шаблона ссылки;
- `DOQA_SPACE_IDS` — пространства только для ручного поиска отчёта в Mini App, по умолчанию
  `2,4,6` (Фаст-трек, Flutter, Native). Команда `/zip` продолжает искать только в
  `DOQA_SPACE_ID`; ручной ZIP не отправляется в QADB и не меняет БД задач;
- `DOQA_API_TIMEOUT_SECONDS` — таймаут одного запроса к DoQA, по умолчанию 60 секунд;
- `DOQA_REPORT_RETRY_DELAYS_SECONDS` — задержки автоматических повторов через запятую,
  по умолчанию `15,60,180`;
- `DOQA_PDF_FONT_PATH` — необязательный путь к TTF-шрифту с кириллицей.
- `QADB_URL` и `QADB_SERVICE_KEY` — адрес и service key QADB; задаются только вместе;
- `QADB_OUTBOX_DIR` — постоянная директория точных ZIP-снимков, по умолчанию
  `task_tracker_data/qadb_outbox`;
- `QADB_SYNC_RETRY_DELAYS_SECONDS` — интервалы фоновой синхронизации, по умолчанию
  `15,60,300,900,3600`; последний интервал повторяется до успешной загрузки.

Docker Compose монтирует `/app/task_tracker_data` в named volume `task_tracker_data`. Поэтому для
включения outbox после обновления достаточно пересобрать и пересоздать app-контейнер:

```bash
docker compose up -d --build --force-recreate app
```

Старые задания, которые уже получили статус `FAILED` до появления outbox, не содержат сохранённого
архива: для них нужно заново вызвать `/zip`. Новые ожидающие синхронизации подхватываются
автоматически.

Для ручного отчёта Mini App получает временную HTTPS-ссылку на ZIP, действующую 10 минут.
Скачивание запускается через нативный `Telegram.WebApp.downloadFile`; для старых клиентов
остаётся запасной переход по HTTPS. Неподдерживаемые `blob:`-ссылки не используются.

Файл проверяется по расширению, PDF-сигнатуре, размеру, числу страниц и наличию парольной
защиты. Парсинг `pdfplumber`, извлечение изображений и создание DOCX выполняются в отдельном
потоке, чтобы бот продолжал отвечать на другие сообщения.
